常见问题与安全清单

遇到的问题基本都在这几张清单里。先看问题，再对一遍检查项，能省掉大部分返工。

上手相关

我完全不会编程，真的能行吗？

能。你要提供的不是编程知识，而是业务知识：文件在哪、字段什么意思、什么情况算异常、结果应该长什么样。这些恰恰是程序员的短板、你的长项。

需要会的只有三件小事：找到文件夹路径、看懂终端里有没有红色报错、会复制粘贴。前两件十分钟就能学会。

AI 写的代码我看不懂，怎么确认它没乱来？

不用逐行看懂，用三个办法替代：

  • 让它自己解释：说「用大白话说明这个脚本会改动哪些文件、有没有删除操作」。
  • 空跑：让它先只打印「将要做什么」，不真正执行。
  • 小批量验证：先处理 3 个文件，打开结果抽查，再放开全量。

真要看代码，重点盯这几个词：remove、unlink、rmtree、move、rename、open(...,'w')。它们对应删除、移动、改名、覆盖，是最需要确认的地方。

它把我的文件改坏了怎么办？

这就是为什么整份指南反复强调先备份。三层保险，按成本从低到高：

  1. 复制一份再动手：处理前把整个文件夹复制成「xxx_备份」。
  2. 输入输出分开：让脚本读 A 文件夹、写 B 文件夹，原文件天然不受影响。
  3. 用版本管理：熟悉以后可以让 Trae 帮你初始化 Git，每次改动都能回退。

如果已经改坏了：先什么都不要再运行，去回收站找，或者用文件恢复工具。同时把现象告诉 Agent，让它分析脚本里哪一步做了覆盖。

为什么它一直让我点「同意」？

因为写文件、跑命令属于有风险的操作，工具默认要你确认。这是保护机制，不是故障。

建议的做法：看一行再点。重点看命令里有没有 del、rm、move，路径是不是在工作区内。批量操作前，先拒绝一次，让它改成「先试 3 个」。

不要为了省事一路开「全部允许」——那等于把刹车拆了。

提示「上下文超限」或聊到后面它开始忘事？

对话太长，最早的记录被挤出去了。两个处理办法：

  • 开新对话，用三五行重新交代：工作区是什么、现在做到哪一步、接下来要做什么。
  • 减少喂给它的内容：不要让它读整本手册，只读相关的那一页；不要贴整张表，只贴表头和两三行。
写好的脚本怎么保存，下次还能用吗？

能，而且很值得。脚本就是一个普通文件（通常是 .py），留在文件夹里就行。做三件事让它可复用：

  • 让它生成 一键运行.bat，以后双击即可；
  • 让它写一个 使用说明.txt，记下用途、前置条件、运行方式；
  • 把「脚本 + 说明 + 启动文件」打包成一个文件夹，按用途命名，比如「合同信息提取工具」。

出错与排查

运行报错了，我该把什么发给它？

把终端里的完整报错复制过去，尤其是最后一行（通常是 XXXError: 具体原因），以及它指向的文件名和行号。不要只说「报错了」。

再加一句现象描述会更准：「我用 3 个文件测试时报的这个错，这 3 个文件里有 1 个是 xls 格式。」

提示「找不到文件 / 路径不存在」

九成是路径写错了。检查三点：

  • 路径是否真实存在，可以直接在资源管理器地址栏粘贴验证；
  • Windows 路径里的反斜杠，在代码里可能需要转义或改用正斜杠；
  • 文件名里的空格、中文括号、全角字符是否一致。

最省事的办法：在资源管理器里选中文件，按住 Shift 右键 →「复制文件地址」，直接粘给它。

脚本在我电脑能跑，同事电脑跑不了？

通常是环境差异。让对方看到报错后告诉你，常见原因有：

  • 没装 Python，或装了但没勾选「Add to PATH」；
  • 缺第三方库（openpyxl、python-docx、Pillow）；
  • 脚本里写死了你电脑的绝对路径（比如 D:\工作\...）。

第三条最容易被忽略。写脚本时就要求：「路径用相对于脚本所在目录的方式，不要写死绝对路径。」

数据安全

!

发给 AI 的内容，等于发给了模型服务商。使用前请先确认公司对数据外发的相关规定；没有明确允许的，按「不能发」处理。

哪些内容绝对不要发给 AI？
  • 身份证号、银行卡号、完整手机号、家庭住址等个人信息；
  • 客户名单、合同原文、未公开的财务数据；
  • 公司内部系统地址、账号密码、数据库连接串；
  • API Key、访问令牌、证书文件；
  • 标注了「机密」「内部」字样的任何材料。

确实需要描述结构时，用假数据替换：把真实姓名换成「张三」，金额换成「1000」，编号换成「A001」。

用了自己的 API Key，会不会很贵？

日常小脚本的消耗很低。估算方式：一次任务大致消耗「输入 + 输出」几千个 token，多数服务商的价格在每百万 token 几元到几十元区间，折算下来单次通常只有几分钱。

真正烧钱的是两种情况：让它反复读大量文件、或者一个任务来回改几十轮。控制办法：只给相关文件、一次说清需求、跑偏了就开新对话。

另外建议在服务商控制台设置消费限额提醒，避免意外。

免费额度用完了怎么办？

三条路：等额度刷新、升级套餐、或者按第 2 章的方法接入自己的 Key。如果公司统一采购了模型服务，找 IT 要 Key 和接口地址，通常比个人付费更划算，也更符合合规要求。

检查清单

把这三张清单存下来，每次照做一遍，能避免 90% 的翻车。

动手前

✓检查项
☐为这次任务单独建了文件夹，没有直接对着桌面或 C 盘操作
☐原始数据已复制备份，或确认输入输出分开存放
☐文件里没有不能外发的敏感信息，或已做脱敏
☐Trae 打开的是正确的文件夹，左侧能看文件列表
☐需求里写清了目标、输入、输出、规则、验收

运行前

✓检查项
☐先空跑过，看过「将要做什么」的输出
☐先用 3 个文件试跑，结果抽查正确
☐确认脚本里没有删除、覆盖原文件的操作
☐确认路径是相对路径，没有写死自己的电脑路径
☐知道跑完后去哪里看结果、怎么回滚

分享前

✓检查项
☐脚本里没有硬编码的 Key、密码、账号
☐没有把你的个人路径、内网地址一起打包出去
☐附了「使用说明.txt」，写明前置条件和运行方法
☐在另一台电脑上试过一次
☐对方知道出问题该找谁、怎么恢复
✓

最后一句话：Agent 让你不必会写代码，但「验证结果」这件事永远得由人来做。它负责快，你负责对。
